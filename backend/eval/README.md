# MCP 工具召回评估

评估检索器能否从用户需求中找到合适的 MCP 工具，比较 BM25、BM25 + 向量、BM25 + 向量 + 重排。只评估召回和排序，不执行目标工具，也不评估答案生成。

## 评估数据

[mcp_tools/tools.jsonl](mcp_tools/tools.jsonl) 包含 200 个工具：100 个 Pi 本机缓存工具、75 个 GitHub 工具和 25 个 Playwright 工具。根据原始名称、description 和 inputSchema 离线整理，每个工具只存一个 chunk，文本仅含**工具名称、功能描述、使用时机**，不拼接 Server、schema 或关键词列表。

每个工具 chunk 的预算上限为 **256 tokens**，按重排模型 tokenizer 计算完整检索文本，不包含模型额外添加的特殊 token。导入和评估前校验，超限报错、不自动截断、不要求写满；现有语料未扩写，实际长度为 42～72 tokens，平均 57.6 tokens。重排仍受“查询 + chunk + 特殊 token”共 512 tokens 的限制。

新版扩写语料单独保存在 [mcp_tools_256](mcp_tools_256/)，根据同一份原始定义补充功能、参数含义及适用边界，仍以 256 tokens 为上限。200 条描述全部重写，实际为 70～191 tokens，平均 108.08 tokens，不要求写满预算。问题、标签和划分沿用原版，生成描述时不读取题目或实验结果；原版与新版结果在下文分别列出。

[mcp_tools/questions.jsonl](mcp_tools/questions.jsonl) 包含 400 条中文需求，覆盖直接查询、语义改写和相似工具辨析，其中 89 条允许多个正确工具。按意图分组、固定随机种子 42 划分为 321 条开发题和 79 条测试题，同组改写不跨集合。问题和标签不进入索引。

原始定义及来源见 [sources.jsonl](mcp_tools/sources.jsonl)，版本、许可证及内容哈希见 [manifest.json](mcp_tools/manifest.json)。公开 schema 由固定提交的官方 README 参数说明重建；本机缓存不代表工具当前在线。根目录的 `questions.yaml` 是原有知识库文档评估集，不参与本次工具评估。

## 评估指标

各指标先逐题计算，再取平均，报告 K = 1、3、5、10。Precision 和 Recall 使用 Ragas 0.4.3 的 ID-based 指标，不需要 LLM 裁判。

| 指标 | 含义 |
|---|---|
| Precision@K | 前 K 个实际返回工具中，正确工具所占比例；分母是实际返回数 |
| Recall@K | 全部标注正确工具中，被前 K 个结果覆盖的比例 |
| Hit@K | 前 K 个结果是否至少命中一个正确工具，命中记 1，否则记 0 |
| MRR@K | 前 K 个结果中首个正确工具排名的倒数，无命中记 0 |
| 候选 / 融合池 Recall | 分别检查原始候选集合、融合截取后的候选池是否覆盖正确工具 |

空召回按失败计入；原始 Precision 为 NaN，汇总按 0 处理并单独计数。重排失败保留回退排名并记录，含失败的配置不参与参数选择。

## 评估流程

使用独立数据库 `sagent_rag_eval`，每工具一个文档、一个 chunk。三条路径使用相同文本，向量模型为 BGE-M3，重排模型为 BGE-reranker-v2-m3；固定 BM25 `k1=1.2`、`b=0.75` 和 RRF `k=60`，不设置最低重排分数。

| 阶段 | 每路召回数 | 融合池 / 重排候选数 | 目的 |
|---|---|---|---|
| 基线 | 40 | 20 | 固定参数，比较三种检索方案 |
| 第一阶段 | 20、40、80 | 20 | 检查扩大召回范围是否减少漏召回 |
| 第二阶段 | 第一阶段选出的值 | 10、20、40 | 比较不同池大小及同一候选池重排前后的结果 |

每路召回数指 BM25 和向量各自取出的工具数，融合池是 RRF 后截取的工具集合，最终 Top K 是返回数。参数仅在开发集上按 Recall@5、MRR@5、较少候选数依次选择，再在测试集验证；不会根据测试结果反向调参。

## 评估结果

开发集选出**每路召回 20、融合池 / 重排候选 20**。以下为 79 条测试题的 Top5 结果：

| 方案 | Precision@5 | Recall@5 | Hit@5 | MRR@5 |
|---|---:|---:|---:|---:|
| BM25 | 20.25% | 86.50% | 89.87% | 0.7308 |
| BM25 + 向量 | 22.28% | 94.09% | 96.20% | 0.7787 |
| BM25 + 向量 + 重排 | 22.03% | **95.78%** | **100.00%** | **0.8947** |

混合检索改善了覆盖，重排进一步改善了前列排名。以下为 321 条开发题的重排后结果，其中 N 是每路召回候选数，M 是融合、去重、RRF 排序后截取的重排候选数：

| 阶段 | 每路召回候选数 N | 重排候选数 M | Recall@5 | Recall@10 | MRR@5 |
|---|---:|---:|---:|---:|---:|
| 第一阶段 | **20** | 20 | **98.55%** | **99.48%** | 0.9126 |
| 第一阶段 | 40 | 20 | 98.23% | 98.86% | 0.9139 |
| 第一阶段 | 80 | 20 | 97.61% | 98.39% | 0.9108 |
| 第二阶段 | 20 | 10 | 98.08% | 99.17% | **0.9139** |
| 第二阶段 | 20 | **20** | **98.55%** | **99.48%** | 0.9126 |
| 第二阶段 | 20 | 40 | 98.39% | 99.17% | 0.9126 |

候选数并非越大越好：两个阶段都按 Recall@5 优先选出 20，且该配置的 Recall@10 也最高。第二阶段 M = 10 的 MRR@5 略高，但覆盖率低于 M = 20。最终返回 Top K = 5 是预先设定的，不是这两阶段调参选出的值。

重排后所有测试题至少命中一个正确工具，但 6 条题仍未覆盖全部标注工具。Hit@5 = 100% 不代表生产准确率 100%；标签是离线整理的评估标注，分阶段调参也不保证全组合最优。最终运行没有空召回、重排失败或 token 截断。

### 256-token 预算

固定 N=20、M=20、Top K=5，使用原来的 79 条测试题，不重新调参。按标注正确工具数分组，逐题计算指标后取平均：

| 正确工具数 | 题数 | 方案 | Recall@5 | MRR@5 |
|---|---:|---|---:|---:|
| 1 | 65 | BM25 | 89.23% | 0.7395 |
| 1 | 65 | BM25 + 向量 | 95.38% | 0.8244 |
| 1 | 65 | BM25 + 向量 + 重排 | **96.92%** | **0.9038** |
| 2 | 12 | BM25 | 75.00% | 0.7917 |
| 2 | 12 | BM25 + 向量 | 95.83% | 0.8333 |
| 2 | 12 | BM25 + 向量 + 重排 | **95.83%** | **1.0000** |
| 3 | 2 | BM25 | 50.00% | 1.0000 |
| 3 | 2 | BM25 + 向量 | 33.33% | 1.0000 |
| 3 | 2 | BM25 + 向量 + 重排 | 50.00% | 0.7500 |

新版重排总体 Recall@5 为 **95.57%**、MRR@5 为 **0.9146**、Hit@5 为 **97.47%**；旧版对应为 95.78%、0.8947、100%。描述扩写改善了总体首个正确工具的排名，但没有提升总体覆盖率，且有 2 条测试题前五名未命中。三个正确工具的分组只有 2 条题，不适合作稳健泛化结论。多答案是可替代工具，MRR 只看首个命中，Recall 则衡量全部标签覆盖。

新版存于评测库的独立 `mcp_tools_256` schema，旧版数据未覆盖。用固定配置入口复现，结果包括按标签数量分组的 `summary.csv`、逐题排名与报告：

```bash
RAG_DEVICE=mps uv run --locked --group eval python -m scripts.eval_mcp_top5 \
  --dataset eval/mcp_tools_256 \
  --output "$HOME/Documents/obsidian/sagent/rag-retrieval/run-256-top5-2026-11-09"
```

已存在的输出目录按指纹恢复，不重新计算已完成结果；从头运行需换新目录。该入口只读测试集，三种方案使用同一份 200 工具语料。

## 复现

在 `backend` 目录执行。需要可连接的 PostgreSQL、`vector` / `pg_textsearch` 扩展，以及 `models/` 下的两个模型；不需要 MCP 服务在线或生成模型 API Key。

```bash
uv sync --locked --group eval
uv run --locked --group eval python eval/mcp_tools/validate_corpus.py
RAG_DEVICE=mps uv run --locked --group eval python -m scripts.eval_mcp_tools run \
  --output "$HOME/Documents/obsidian/sagent/rag-retrieval/run-reproduce"
```

使用新的输出目录会重新执行检索和重排；已有目录在指纹匹配时恢复并复用结果。模型、语料、运行实现或数据库状态不匹配时拒绝混用，业务数据库和默认参数不受影响。

256-token 校验加入后运行指纹已更新，新实验需使用新的输出目录；下面归档的历史结果仍可通过 `score` 重新计分。

本次结果保存在 `~/Documents/obsidian/sagent/rag-retrieval/run-2026-11-09-final/`：`summary.csv` 为各阶段、来源分组及多 K 指标，`rankings.jsonl` 为逐题候选和排名，`report.md` 为完整报告。仅根据已有排名重新计分，不访问数据库或加载模型：
